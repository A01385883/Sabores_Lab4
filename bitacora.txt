Declaración Uso de IA:

Promt / Respuesta:
Ok, puedes explicarme los problemas con mi archivo, y porque tengo 4 elementos que me salen como sin declarar?

¡Claro! Vamos por partes.
1. El problema de fondo: UiState<Detalle> no es lo mismo que Detalle
En tu ViewModel tienes esto:
var detalle by mutableStateOf<UiState<Detalle>>(UiState.Cargando)
detalle no es un objeto Detalle que puede ser null — es un UiState que envuelve a un Detalle. UiState es un sealed interface con tres formas posibles:
sealed interface UiState<out T> {
    data object Cargando : UiState<Nothing>
    data class Exito<T>(val datos: T) : UiState<T>
    data class Error(val mensaje: String) : UiState<Nothing>
}
Así que cuando escribías viewModel.detalle.restaurant, el compilador ve un UiState<Detalle> y busca la propiedad restaurant en el UiState, no en el Detalle de adentro — y como UiState no tiene esa propiedad, marca "Unresolved reference".
2. Por qué el ?: no ayudaba
Tenías viewModel.detalle ?: return@composable. El operador ?: (elvis) solo hace algo si el valor de la izquierda puede ser null. Pero detalle es de tipo UiState<Detalle>, que nunca es nulo (siempre es Cargando, Exito o Error, nunca null). Entonces ese ?: no filtraba nada — el problema seguía sin resolverse.
3. La solución: desempacar con when, igual que ya hacías en HOME
Fíjate que arriba, en la ruta HOME, tú mismo ya resolvías este mismo patrón correctamente:
when (val estado = viewModel.restaurantes) {
    is UiState.Cargando -> CargandoView()
    is UiState.Error -> ErrorView(...)
    is UiState.Exito -> RestaurantListScreen(restaurants = estado.datos, ...)
}
Apliqué exactamente esa misma idea a detalle:
when (val estado = viewModel.detalle) {
    is UiState.Cargando -> CargandoView()
    is UiState.Error -> ErrorView(
        mensaje = estado.mensaje,
        onReintentar = { viewModel.cargarDetalle(id) }
    )
    is UiState.Exito -> {
        val detalle = estado.datos          // <- aquí sí es un Detalle real
        RestaurantDetailScreen(
            restaurant = detalle.restaurant,
            summary = detalle.summary,
            reviews = detalle.reviews,
            ...
        )
    }
}
Cuando Kotlin entra al is UiState.Exito, hace smart cast: sabe que estado ya es un UiState.Exito<Detalle>, así que estado.datos es directamente un Detalle — ahí sí existen .restaurant, .summary y .reviews.
4. El segundo lugar (ruta NEW_REVIEW)
Ahí solo necesitabas el restaurant, no todo el when, así que usé un cast seguro en una sola línea:
val restaurant = (viewModel.detalle as? UiState.Exito)?.datos?.restaurant
    ?: return@composable
Esto dice: "si detalle es de tipo UiState.Exito, tómalo; si no lo es (está Cargando o Error), dame null". El as? es un cast que no truena si falla, solo devuelve null. Luego ?.datos?.restaurant navega con seguridad, y el ?: return@composable sale de la pantalla si todavía no hay restaurante cargado.
5. El import duplicado
Solo tenías import androidx.compose.runtime.LaunchedEffect escrito dos veces (líneas 12 y 31). No era la causa del error, pero Kotlin lo marca como conflicto de import, así que lo quité de paso.
